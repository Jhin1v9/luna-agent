Sistema de Créditos Nexo Digital

Guía de uso del sistema de créditos, suscripciones y tickets de servicio. Todas las APIs son servidas por nexo-dashboard-backend en https://vps.nexo-digital.app:3500 (proxy a 127.0.0.1:13500).

1. Conceptos

TérminoSignificado
PlanDefine créditos mensuales, precio, hosting y nivel de soporte (básico, profesional, premium, enterprise).
SuscripciónAsocia un clientId (ID de organización) a un plan. Tiene estado (active/cancelled), periodo actual y auto-renovación.
CréditoUnidad de trabajo. 1 crédito ≈ 1 hora de trabajo del equipo. Se asignan, consumen y reservan.
TicketSolicitud de servicio del cliente. Flujo: pendiente → cotizado (créditos estimados) → aprobado (reserva) → en_progreso → completado.
Auto-assignAsignación mensual automática de créditos a todas las suscripciones activas.

3. APIs — Lado Cliente (público, sin auth)

3.1 Saldo del cliente

GET /api/credits/client/:clientId/balance
Retorna credits (balance, totalAssigned, totalConsumed, totalReserved), subscription activa, plan contratado y nextAssignment (fecha y monto de la próxima recarga).

3.2 Historial de transacciones

GET /api/credits/client/:clientId/transactions
GET /api/credits/client/:clientId/transactions?type=asignacion&from=2026-07-01&to=2026-07-31
Devuelve el array transactions y groupedByMonth agrupado por mes con totales.

3.3 Perfil unificado

GET /api/credits/client/:clientId/profile
Retorna organización, créditos, suscripción, proyectos, contratos, tickets, usuarios del equipo y últimas 20 transacciones. Es el endpoint que usa el portal del cliente (workspace-cliente).

3.4 Tickets

GET  /api/service-tickets/client/:clientId     — listar tickets del cliente
POST /api/service-tickets                        — crear ticket (clientId, title, description, category, priority)
POST /api/service-tickets/:id/approve             — aprobar ticket (cliente, reserva créditos)

4. APIs — Lado Admin Requiere auth

Autenticación: Authorization: Bearer <token> (JWT de sesión) o x-internal-token: nexo-digital-2026 (fallback).

4.1 Resumen global

GET /api/credits/admin/summary
Total de clientes con créditos, balance/reservado/consumido/asignado global, tickets pendientes y activos.

4.2 Dashboard de todos los clientes

GET /api/credits/admin/clients
Array de clientes con su creditId, balance, suscripción y conteo de tickets pendientes/activos.

4.3 Perfil completo del cliente (admin)

GET /api/credits/admin/client/:clientId/profile
Igual que el perfil del cliente + creditHistory completo, internalCredits consumidos por el equipo, y transacciones de equipo.

4.4 Ajustar créditos

POST /api/credits/admin/client/:clientId/adjust

Body: { amount, description, referenceType, referenceId }

Cantidad positiva = asigna créditos. Negativa = descuenta. No permite saldo negativo. Tipos de referencia: plan, admin, ticket.

4.5 Gestionar suscripción

POST /api/credits/admin/client/:clientId/subscription

Body: { planId, autoRenew?, hostingAddon? }

Asigna/actualiza la suscripción del cliente. Estado inicial: active.

4.6 Asignación mensual automática

POST /api/credits/admin/auto-assign-monthly

Body: { clientId? } (opcional; si se omite, aplica a todas las suscripciones activas).

Suma plan.creditsPerMonth al balance de cada suscripción activa. Debe ejecutarse manualmente (no hay cron integrado).

4.7 Gestión de planes

POST /api/credits/admin/plans

Body: { id, name, description, creditsPerMonth, priceMonthly, hostingIncluded, supportLevel, features[] }

4.8 Uso del equipo (team-usage)

POST /api/credits/admin/client/:clientId/team-usage

Body: { userId, amount, description, projectId? }

amount debe ser negativo. Registra el consumo en Prisma (CreditTransaction tipo usage) y en el dashboard como consumo_team. No descuenta del balance del cliente.

4.9 Tickets (admin)

GET  /api/service-tickets/all                   — todos los tickets
POST /api/service-tickets/:id/quote             — cotizar (estimatedCredits > 0, cambia a "cotizado")
PUT  /api/service-tickets/:id/status            — cambiar estado (status, actualCredits?, assignedTo?)
Al poner status completado, los créditos reservados se convierten en consumo.

5. Flujo de trabajo

5.1 Crear organización con plan

Cuando se crea una organización en workspace-nexo (POST /api/admin/organizations):

  1. Se crea Organization → Project → Contract.
  2. Se crea el usuario admin con bcrypt (rol seleccionable: ADMIN, MANAGER, MEMBER, VIEWER).
  3. Se asigna suscripción en el dashboard backend (/credits/admin/client/:id/subscription).
  4. Se asignan los créditos iniciales del plan en el dashboard backend (/credits/admin/client/:id/adjust).
  5. Se sincronizan los créditos hacia Prisma (workspace-nexo): CreditTransaction tipo plan + WorkspaceUser.credits.

5.2 Ciclo de vida de un ticket

Cliente crea ticket
  └─ POST /service-tickets  { clientId, title, description, category, priority }
      → status: "pendiente"

Admin cotiza
  └─ POST /service-tickets/:id/quote  { estimatedCredits }
      → status: "cotizado"

Cliente aprueba
  └─ POST /service-tickets/:id/approve
      → Reserva créditos del balance (type: "reserva")
      → status: "aprobado"

Admin ejecuta
  └─ PUT /service-tickets/:id/status  { status: "en_progreso" }

Admin completa
  └─ PUT /service-tickets/:id/status  { status: "completado", actualCredits }
      → Convierte reserva en consumo
      → Si actualCredits < estimatedCredits, devuelve diferencia

5.3 Asignación mensual

POST /api/credits/admin/auto-assign-monthly
POST /api/credits/admin/auto-assign-monthly  { "clientId": "org-123" }
El endpoint NO se ejecuta automáticamente. Debe invocarse manualmente cada mes (o configurar un cron externo).

6. Ejemplos con cURL

6.1 Ejemplos — Cliente

# Ver saldo
curl -s https://vps.nexo-digital.app:3500/api/credits/client/org-123/balance | jq

# Ver historial
curl -s https://vps.nexo-digital.app:3500/api/credits/client/org-123/transactions | jq

# Perfil unificado
curl -s https://vps.nexo-digital.app:3500/api/credits/client/org-123/profile | jq

# Crear ticket
curl -s -X POST https://vps.nexo-digital.app:3500/api/service-tickets \
  -H 'Content-Type: application/json' \
  -d '{"clientId":"org-123","title":"Actualizar SSL","description":"Renovar certificado","category":"hosting","priority":"alta"}' | jq

# Aprobar ticket
curl -s -X POST https://vps.nexo-digital.app:3500/api/service-tickets/ticket-id/approve | jq

6.2 Ejemplos — Admin

TOKEN="nexo-digital-2026"
BASE="https://vps.nexo-digital.app:3500"

# Resumen global
curl -s "$BASE/api/credits/admin/summary" -H "x-internal-token: $TOKEN" | jq

# Dashboard de clientes
curl -s "$BASE/api/credits/admin/clients" -H "x-internal-token: $TOKEN" | jq

# Ajustar créditos (+500)
curl -s -X POST "$BASE/api/credits/admin/client/org-123/adjust" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" \
  -d '{"amount":500,"description":"Bono de bienvenida"}' | jq

# Asignar suscripción
curl -s -X POST "$BASE/api/credits/admin/client/org-123/subscription" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" \
  -d '{"planId":"premium","autoRenew":true,"hostingAddon":true}' | jq

# Auto-assign mensual
curl -s -X POST "$BASE/api/credits/admin/auto-assign-monthly" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" | jq

# Cotizar ticket
curl -s -X POST "$BASE/api/service-tickets/ticket-id/quote" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" \
  -d '{"estimatedCredits":5}' | jq

# Cambiar estado de ticket
curl -s -X PUT "$BASE/api/service-tickets/ticket-id/status" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" \
  -d '{"status":"completado","actualCredits":4}' | jq

# Perfil completo con historial
curl -s "$BASE/api/credits/admin/client/org-123/profile" \
  -H "x-internal-token: $TOKEN" | jq

# Registrar uso interno del equipo
curl -s -X POST "$BASE/api/credits/admin/client/org-123/team-usage" \
  -H 'Content-Type: application/json' -H "x-internal-token: $TOKEN" \
  -d '{"userId":"user-id","amount":-3,"description":"Ajustes de CSS"}' | jq

7. Estados y transiciones de tickets

EstadoSignificadoTransición
pendienteRecién creado por el cliente→ cotizar
cotizadoAdmin asignó créditos estimados→ aprobar (cliente)
aprobadoCliente aprobó, créditos reservados del balance→ en_progreso
en_progresoEquipo trabajando→ completado
completadoFinalizado. Reserva → consumo. Si actualCredits < estimatedCredits, se devuelve diferencia.—
canceladoCancelado. Si tenía reserva, se libera.—

8. Tipos de transacción

TipoOrigenEfecto en balance
asignacionAdmin (adjust, auto-assign, creación de org)+ amount
reservaAprobar ticket− amount (se reserva)
consumoCompletar ticket— (la reserva se convierte)
ajusteAdmin adjust con amount < 0− amount
rolloverPropagación de saldo entre periodos (manual)+ amount
consumo_teamAdmin team-usageSin efecto (solo registro)

9. Notas importantes

  • Doble sistema: Los créditos se gestionan en el dashboard backend (JSON en disco) y se sincronizan a Prisma (workspace-nexo) al crear organización. El portal del cliente lee de ambos: /api/credits/balance (Prisma) + /api/credits/profile (dashboard).
  • Auto-asignación mensual: No hay cron automático. Debe ejecutarse POST /api/credits/admin/auto-assign-monthly manualmente al inicio de cada mes.
  • Saldo negativo: El sistema rechaza ajustes que resulten en saldo negativo. Los tickets requieren saldo suficiente para aprobarse.
  • Auth: Endpoints admin requieren token interno (x-internal-token) o JWT de sesión. El valor del token interno es el mismo que DASHBOARD_API_KEY en workspace-nexo.
  • URL base: https://vps.nexo-digital.app:3500 (pública, vía Caddy reverse proxy a 127.0.0.1:13500).
