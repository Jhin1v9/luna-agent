# Luna Monorepo Installer Design

## Overview

Create a one-command installer for the `luna-kernel` monorepo that works on a fresh Linux/WSL machine. The installer clones the repo, installs system dependencies if needed, generates runtime configuration, builds the project, starts PM2, and guides the user through the only manual step: logging into Kimi.

The installer must not contain hardcoded paths from the original developer's PC. It derives all paths from the user's home directory and environment variables.

## Goals

- One-command setup: `bash <(curl -fsSL https://raw.githubusercontent.com/Jhin1v9/luna-kernel/main/install.sh)`
- Works on a machine with nothing installed (bootstraps Node, pnpm, PM2, Chrome on demand).
- Generates secure tokens automatically.
- Does not require the end user to handle Telegram bot tokens (bot runs on the owner's PC).
- Leaves the user with working `luna` and `dashboard` terminal shortcuts.
- Only manual step: log into Kimi in the isolated Chrome profile.

## Non-Goals

- Cross-platform support for macOS/Windows in v1 (Linux/WSL only).
- Migrating existing `~/.luna-kernel` data automatically from old installs.
- Installing/configuring PostgreSQL automatically (JSON fallback is acceptable for a first boot).
- Handling headless/CI installs.

## Architecture

### Bootstrap (`install.sh`)

A POSIX-compatible shell script that:

1. Detects OS (Linux/WSL allowed, aborts on others).
2. Checks for Node.js v22+; offers to install if missing.
3. Checks for pnpm; offers to install via corepack if missing.
4. Checks for PM2; offers to install globally via npm if missing.
5. Checks for Google Chrome/Chromium; offers to install via apt if missing.
6. Resolves install directory: `${LUNA_DIR:-$HOME/.luna-kernel}`.
7. If the directory exists, asks: update existing / overwrite / cancel.
8. Clones `https://github.com/Jhin1v9/luna-kernel.git` into the resolved directory.
9. Runs `node install.cjs` inside the cloned repo.

### Installer Logic (`install.cjs`)

A Node script that:

1. Reads `LUNA_DIR` from the environment.
2. Sets `LUNA_HOME=${LUNA_HOME:-$HOME/.luna}`.
3. Prompts for:
   - Luna Web port (default 3458)
   - Dashboard port (default 3456)
   - Whether to start Vite dev server (default yes)
4. Generates automatically:
   - `JWT_SECRET` (64-char hex)
   - `INTERNAL_API_TOKEN` (64-char hex)
   - `LUNA_HOME`, `LUNA_KERNEL_DIR`, `LUNA_DIR`, `NEXO_DIR` pointing into the install directory.
5. Writes `.env` files:
   - `apps/dashboard/.env`
   - `packages/kernel/.env`
6. Runs `corepack pnpm install`.
7. Runs `corepack pnpm build`.
8. Generates `pm2-ecosystem.config.js` **without** `telegram-bot`.
9. Creates `~/.local/bin/luna` and `~/.local/bin/dashboard` shortcuts.
10. Starts PM2: `pm2 start pm2-ecosystem.config.js && pm2 save`.
11. Launches isolated Chrome profile and opens a local wizard HTML.
12. Waits for user confirmation that Kimi login is done.

## Generated `.env`

```env
NODE_ENV=production
LUNA_HOME=/home/<user>/.luna
LUNA_KERNEL_DIR=/home/<user>/.luna-kernel/packages/kernel
LUNA_DIR=/home/<user>/.luna-kernel/packages/kernel
NEXO_DIR=/home/<user>/.luna-kernel/apps/dashboard
LUNA_PORT=3458
DASHBOARD_PORT=3456
JWT_SECRET=<auto-generated>
INTERNAL_API_TOKEN=<auto-generated>

# Optional: uncomment and fill to enable extra features
# TELEGRAM_BOT_TOKEN=
# GEMINI_API_KEY=
# SMTP_HOST=
# SMTP_USER=
# SMTP_PASS=
# GMAIL_CLIENT_ID=
# GMAIL_CLIENT_SECRET=
# DATABASE_URL=
```

## PM2 Ecosystem

The installer writes a generated `pm2-ecosystem.config.js` with the same five apps as the repo default, but **omits `telegram-bot`**. The repo still ships the full `pm2-ecosystem.config.js` for owners who want the bot.

## Terminal Shortcuts

### `luna`

```bash
#!/bin/bash
ECO="$HOME/.luna-kernel/pm2-ecosystem.config.js"
if pm2 status | grep -qE "luna-server|nexo-dashboard"; then
  pm2 restart all
else
  pm2 start "$ECO"
fi
pm2 save
xdg-open "http://localhost:3458" 2>/dev/null || true
xdg-open "https://localhost:5173" 2>/dev/null || true
```

### `dashboard`

```bash
#!/bin/bash
ECO="$HOME/.luna-kernel/pm2-ecosystem.config.js"
if pm2 status | grep -qE "luna-server|nexo-dashboard"; then
  pm2 restart all
else
  pm2 start "$ECO"
fi
pm2 save
xdg-open "http://localhost:3456" 2>/dev/null || true
```

## Kimi Login Wizard

A static HTML file (`install-wizard.html`) generated/shipped in the repo, opened via `xdg-open`. It instructs the user to:

1. Wait for Chrome to open.
2. Open `http://localhost:9222/json`.
3. Click the Kimi tab link.
4. Log in manually.
5. Return and close the wizard.

The installer waits for a key press after the wizard is opened.

## Error Handling

- Node missing → prompt to install, abort if declined.
- pnpm install fails → retry once after `pnpm store prune`.
- pnpm build fails → print last 50 lines and abort.
- Port in use → suggest incrementing port and retry.
- Chrome missing → prompt to install, abort if declined.
- `~/.local/bin` not in PATH → warn and append to `~/.bashrc`.

## Security Notes

- Tokens are generated with `crypto.randomBytes(32).toString('hex')`.
- `.env` files are gitignored and never committed.
- The installer does not persist Telegram tokens or database credentials.
